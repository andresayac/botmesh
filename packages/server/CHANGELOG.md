# @botmesh/server

## 1.0.0-beta.0

### Major Changes

- 821d766: First public release of `@botmesh/server` (webhook ingress: raw body, size and time limits, concurrency cap, health endpoints, adapters for `node:http`, Express, Fastify and Hono), `@botmesh/events` (event envelopes, leased journals with fencing tokens, `EventWorker` with retries and a dead-letter state, and the bot durability backend in `@botmesh/events/durability`) and `@botmesh/otel` (OpenTelemetry tracer and `bot.metrics()` bridge for `@botmesh/core`). Their API is frozen and covered by semver from 1.0.0. Engine helpers left the main entries: `normalizePath`/`splitUrl` are in `@botmesh/server/internal` and `SpanMetrics`/`METRIC_SOURCE_KEYS` in `@botmesh/otel/internal` (no semver); the `__testing` seam of `@botmesh/events` is no longer exported, and its `AppendLogOptions` type is.

### Patch Changes

- 591b510: README fixes: the `@botmesh/server` examples mount `TelegramProvider` without the `body: 'text'` it no longer needs; `@botmesh/graph-core` names Messenger and Instagram as its other dependents; Twilio explains that the core splits text over 1600 characters; Gupshup's `webhookTokenParam` is also read by `ingest()` with a URL; Evolution says poll votes are not emitted as `'poll'` events yet (it named a `poll-vote` event that does not exist); and the prerelease notes of the packages first published in the beta no longer mention an older alpha.
- bb1fd93: The request URL handed to `ingest()` (third argument) now carries the query string exactly as received instead of `URLSearchParams.toString()`, which re-encoded it. `IngressRequest` takes an optional `rawQuery` (filled by `createNodeHandler`, the Express/Fastify/Hono adapters and `createFetchHandler`; custom adapters that omit it keep the old behaviour) and `splitUrl()` returns it. Before, `TwilioProvider` with `webhookPath` behind `@botmesh/server` answered 403 to every correctly signed request whose console URL had a query such as `?tenant=a%20b`, `?flag`, `?next=/x` or `?t=~x`.
- a472dda: Release-test fixes: an `ingest()` status is used only when it is an integer 200-599 (a `1xx` code used to hang the client on `node:http` and throw on the fetch path), `205` no longer throws in `serveFetch`/Hono, `/readyz` answers `503` instead of rejecting when `bot.getConnectionState()` throws, absolute-form request targets are routed by their path, and configuration mistakes (missing `routes`, an unknown `body` mode, `healthPath` equal to `readyPath`, a `bot` without `getConnectionState()`, a timeout `setTimeout` would clamp to 1 ms, an invalid `close()` timeout) throw a `TypeError` naming the option. The docs now say that the request URL reaches `ingest()` as its third argument.
- 63b7713: Headers returned by `ingest()` as `{ status, body, headers }` now replace the ingress's own headers case-insensitively (`Content-Type` no longer yields `application/json; charset=utf-8, application/json`), and framing/hop-by-hop headers (`content-length`, `transfer-encoding`, `connection`, `keep-alive`, `upgrade`, `proxy-connection`, `te`, `trailer`) are dropped, so a result can no longer produce a response with conflicting lengths that clients reject.
