    Interface BotConfig

    Options of new Bot(config). Only provider is required. Every duration option takes a string ('30s', '5m') or milliseconds; the constructor validates them and throws ConfigValidationError naming the option.

    Example

    import { Bot, MemoryStore } from '@botmesh/core'
    import { TelegramProvider } from '@botmesh/telegram'

    const bot = new Bot({
      provider: new TelegramProvider({ token: process.env.TELEGRAM_TOKEN! }),
      store: new MemoryStore({ file: './data/store.json' }),
      lang: 'es', // built-in texts in Spanish (default 'en')
      typing: true, // show "typing…" before text replies
    })

    OptionalsplitLongText

    splitLongText?: boolean

    Split a text send longer than the provider's capabilities.maxTextLength (UTF-16 code units) or capabilities.maxTextBytes (UTF-8) into several messages, sent in order at paragraph, line, sentence or word boundaries, never inside a grapheme (emoji, flags) or the chat's markup (a code block, inline code, a bold run or an HTML element longer than the limit is closed and reopened; links and URLs stay whole). before('send') hooks run once on the whole text and what they return is split (so a footer is added once and every part still fits; a hook that makes a short text too long gets it split too, its explicit key then suffixed from #1); an abort skips the whole text. Each part is then a send of its own: after('send') hooks, the message log and the durable outbox see each part. Only the first part keeps options.quoted; an explicit idempotencyKey gets a #2, #3… suffix from the second part on. The result is the last part's, with parts listing every part. A part that fails rejects the send and the remaining parts are not sent, except when the durable outbox defers it (SendDeferredError): the remaining parts are then journaled behind it and the sweeper delivers them too. bot.enqueue() journals one record per part (<key>, <key>#2…). Edits and ctx.stream() (which splits on its own) are not affected, and the outbox sweeper sends a record as it was journaled. Default true; false sends the text as given (the provider may then reject it with PayloadTooLargeError).

    Optionaldedupe

    dedupe?: false | InboundDedupeOptions

    Inbound idempotency: a redelivered message/interaction (webhook retry, reconnect replay) never runs handlers twice. Keyed by chatId + ref.id (interactions: interactionId), bounded LRU with optional TTL. Enabled by default ({ size: 1000 }); false disables it. Relies on the providers' INBOUND ID CONTRACT (see IProvider). Runs after the access lists: a blocked delivery is never recorded, so a redelivery after un-blocking is processed. See InboundDeduper.

    OptionalechoFilter

    echoFilter?: true | EchoFilterOptions

    Echo filter (opt-in): remember the refs of the bot's successful sends (bounded LRU, optional TTL) and drop an inbound message carrying one of them BEFORE the access lists, dedupe, journaling and counters — a provider-independent guard for transports that hand the bot's own messages back without fromMe (a mailbox, a gateway, a selfId learned late). true = { size: 1000 }. Counted in metrics().dropped.echo. Complements the provider's fromMe (the primary guard); omitted = off, as before.

    Optionaldurability

    durability?: DurabilityConfig

    Durable message processing: journal every admitted inbound event before dispatch (replayed after a crash) and every send in an outbox with idempotency keys, retries, backoff and a dead-letter queue. Omitted = off (in-memory, exactly as before); {} = on with the in-memory backend. See DurabilityConfig and the operations guide.

    OptionalrateLimitRetry

    rateLimitRetry?: false | RateLimitRetryOptions

    In-place retry of a ctx send (reply/say/media in handlers, flows and conversations) that the transport rejects with a RateLimitedError asking for a short wait: the send waits retryAfterMs and is tried again (same payload, hooks not re-run), so a conversation step does not end on a transient 429. Default { retries: 1, maxWaitMs: 5000 }: one retry, only when the wait is at most 5 s. A longer wait, other errors and bot.send() fail as before (broadcasts and the durable outbox have their own back-off). false disables it. retries counts attempts AFTER the first, like every retries option.

    OptionallogIds

    Optionalcoordination

    coordination?: CoordinationConfig

    Run this bot as one of N replicas sharing a backend (opt-in). Each chat is processed by one replica at a time, in ingress order, and an exclusive transport session (Baileys) is connected by the elected replica only. Omitted: a single process, as always.
