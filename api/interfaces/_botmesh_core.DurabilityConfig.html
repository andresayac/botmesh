    OptionalinstanceId

    instanceId?: string

    Lease owner of this process. Keep it STABLE across restarts of the same deployment (a restarted process then reclaims its own in-flight records at once, without waiting for their leases to expire) and UNIQUE per concurrently running replica (two live processes with one id would take each other's leases).

    Default: <hostname>/<botId>/<connectionId> on a single-process backend (memory, file); on a shared backend (Postgres, Redis) that id plus a per-boot suffix, so two processes on one host never share it — a restart then waits for the old leases to expire.

    failOpen?: boolean

    Type Declaration

    • OptionalleaseMs?: string | number

      Processing lease (heartbeat-extended while the event is running). Default 60_000 ms.

    • OptionalmaxAttempts?: number

      Attempts before an event whose processing keeps failing is dead-lettered. Default 5.

    • Optionalbackoff?: RetryBackoff

      Backoff between failed attempts. Default { baseMs: 1000, capMs: 60000, jitter: 0.2 }.

    • OptionalmediaRefs?: boolean

      Journal a serializable reference to each message's media (IProvider.serializeMediaRef) so a replayed message (crash recovery, background retry) can still download it (IProvider.rehydrateMediaRef). Only applies to providers with those hooks. The reference grants access to the media, like the message body stored next to it. false: journal media tokens as they are, as before (a replayed message may then be unable to download its media). Default true.

    Type Declaration

    • Optionalretries?: number

      Retries after the first attempt before a send is dead-lettered. Default 5.

    • Optionalbackoff?: RetryBackoff

      Backoff between attempts (a RateLimitedError waits at least its retryAfterMs). Default as inbox.backoff.

    • OptionalinlineMaxMs?: string | number

      How long a ctx.reply / bot.send keeps retrying inline before it rejects with SendDeferredError and leaves the send to the background sweeper. Default '15s'.

    • OptionalonAmbiguous?: "skip" | "resend"

      A send whose outcome is unknown after a crash (the provider was called, the result was never recorded): 'skip' (default) marks it unknown — possible loss, never a duplicate; 'resend' sends it again — never a loss, possible duplicate.

    • OptionalmaxPayloadBytes?: number

      Encoded payloads above this size bypass the outbox (sent directly, with a warning). Default 1 MiB.

    • OptionalleaseMs?: string | number

      Lease of a send in flight (heartbeat-extended while the provider call runs). Default 60_000 ms.

    • OptionalonDiverged?: "send" | "skip"

      A replayed handler whose n-th send differs from the one recorded under the same derived key (<inboundId>:<n>) took another path (e.g. a non-persistent flow lost on a crash): 'send' (default) sends the new content under a new key — never a lost reply; 'skip' answers it with the recorded ref, as if it were the same send. Explicit idempotencyKeys are never compared: the caller names the send.
