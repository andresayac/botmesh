    Optional ReadonlysetCheckpointIf

    setCheckpointIf?: (
        key: string,
        cp: FlowCheckpoint,
        expectedRevision: number,
    ) => Promise<boolean>

    Compare-and-set checkpoint write (multi-replica coordination). Succeeds (resolves true) only when the stored row's FlowCheckpoint.revision equals expectedRevision, where 0 means "no row, or a row without revision"; otherwise the row is left untouched and it resolves false. ONE atomic statement per store (never a read-modify-write), so two replicas racing on one key see exactly one winner. expectedRevision is a non-negative integer (RangeError otherwise). Optional: a store without it keeps the local-fence behaviour; all six built-in stores implement it and pass the shared conformance block (test-utils/store-conformance.ts).

    Implementation of IStore.setCheckpointIf

    Optional ReadonlyclearCheckpointIf

    clearCheckpointIf?: (key: string, expectedRevision: number) => Promise<boolean>

    Conditional delete: true when the row is absent, or its revision (0 without one) matched expectedRevision and it was deleted; false when a different revision is stored (the row is left untouched). Same atomicity rule as setCheckpointIf.
