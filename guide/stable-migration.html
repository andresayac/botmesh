Upgrade to stable: checklist and API changes ​

The stable line (@botmesh/core 2.0.0, the other public packages 1.0.0) freezes the public API. The beta (@botmesh/core 2.0.0-beta, the other public packages 1.0.0-beta) already ships it, so these pages also cover upgrading from an alpha to the beta. Coming from a 2.0 alpha, most code keeps running: renamed APIs keep a @deprecated alias (your editor strikes them through), and the few hard breaks are marked Breaking on these pages.

Upgrade checklist ​

Work through it in order; each step links to the details.

  1. Upgrade every @botmesh/* package together, to the same release line. Mixing an old core with newer channel packages is not supported.
  2. Dependencies (details): install ffmpeg if your Baileys bot sends voice notes, move Gemini bots to @google/genai, check the redis peer range and the Graph API version, and update dashboards that read botwa_* metrics.
  3. Run the type checker (tsc --noEmit) and fix what it reports (details below): imports that moved to @botmesh/core/spi, /testing or /internal, @botmesh/ai/testing, @botmesh/baileys/internal and the removed RedisStore APIs.
  4. Replace the deprecated names (table): ctx.reply instead of ctx.say, flow instead of addKeyword, bot.send, bot.plug for plugins, bot.trigger, onType… They still work, but they are removed in v3.
  5. Review the behaviour changes (details). The two most bots need: lang: 'es' if your bot speaks Spanish (built-in texts are now English), and maxAttempts: N where a wait set retries: N.
  6. Read the notes for your channels and plugins (details).
  7. Run your tests and start the bot once with a bot.on('error', …) listener. Watch for the one-time retries warning and for ConfigValidationError, which now names any invalid duration option.

bot.enterConversation(handler, ctx) with an inline handler is not deprecated: it is the way to start a conversation that is not registered.

BotConfig.storeConfig now has a type (file, maxMessagesPerChat, autoSaveInterval), and the bot logs a warning when it is set. Setting durability.backend and durability.journal to two different backends throws a ConfigValidationError.

Plugins: one instance per name ​

Breaking: bot.plug() throws when a plugin with the same name is already plugged. Before, the second instance was installed too and both ran their handlers. To plug a plugin again, call the unplug function first. A plugin built to run several times sets multiple: true in its spec:

ts
definePlugin({ name: 'webhook', version: '1.0.0', multiple: true, install(ctx) { /* … */ } })

Durations ​

Every duration option of BotConfig takes a duration string or a number of milliseconds, including all *Ms options. typing.minMs, typing.maxMs and the durability backoff.baseMs / backoff.capMs accepted only numbers before; they now accept '800ms', '1s' and so on.

Breaking (stricter validation): new Bot() now parses every duration option and throws a ConfigValidationError naming it (err.field === 'coordination.turnWaitMs') when a value cannot be read. Before, some invalid values only failed later, with a message that did not name the option, and null was accepted for a few of them.

Logger ​

The LoggerLike contract is unchanged, and its calling convention is now documented: the packages call logger.warn('message') or logger.warn({ err, ...context }, 'message'), as pino does. See Logging.

@botmesh/baileys: entries and native types ​

The main entry keeps what an application needs (BaileysProvider, its options, toJid, isEditedMessage, RateLimiter, the PollStore types). The rest moved to @botmesh/baileys/internal, which has no semver guarantee; the old names stay on the main entry as @deprecated aliases until v3.

  • Breaking: toInbound and toOutbound are no longer exported by @botmesh/baileys: their signatures use Baileys' own types. Import them from @botmesh/baileys/internal.

  • Breaking (types only): Baileys' native values are opaque. provider.socket is BaileysSocket | null, provider.auth is BaileysAuthState, and the raw / native of messages, refs and send results are BaileysNativeMessage; the three are unknown aliases. Nothing changes at runtime. Use socketOf(provider) and authStateOf(provider) from @botmesh/baileys/internal for typed handles, or cast with your own @whiskeysockets/baileys import:

    ts
    // before
const sock = provider.socket
// after
import { socketOf } from '@botmesh/baileys/internal'
const sock = socketOf(provider)

  • The JID predicates (isGroup, isPn, isLid, isBroadcast, isNewsletter) return boolean instead of boolean | undefined (undefined is now false).

  • pairingCode is renamed pairingPhoneNumber (the value was always the phone number); passing both with different numbers throws a TypeError.

@botmesh/redis-store ​

Breaking: the cluster key-layout internals moved to a new subpath without a semver promise, @botmesh/redis-store/internal. The layout option, the RedisKeyLayout type, migrateToClusterLayout(), inspectKeyspace(), isRedisClusterClient() and withClusterRetry() stay on the main entry.

NamesImport from
INDEX_BUCKETS, LAYOUT_MARKER, bucketOf, encodeSegment, hashSlot@botmesh/redis-store/internal (still re-exported by the main entry, @deprecated)
storeKeys, coordKeys, scheduleKeys, userDataKeys, hashTagOf, assertOneSlot, assertLayoutPrefix and the key types@botmesh/redis-store/internal (new; never exported before)

Breaking: two deprecated APIs were removed.

RemovedUse
new RedisStore({ ttl: 3600 }) (seconds)new RedisStore({ sessionTtl: '1h' }) (a duration or milliseconds). Passing ttl from JavaScript throws a TypeError that names the replacement.
store.acquireLock(key, ttlMs) → token | nullstore.acquireLockFenced(key, ttlMs) → { token, fence } | null; release with releaseLock(key, lock.token). ts
// Before
const token = await store.acquireLock(`job:${id}`, 30_000)
// After
const token = (await store.acquireLockFenced(`job:${id}`, 30_000))?.token

The client contracts did not change shape: their request and response types are now written inline, so a fake client typed AnthropicLike (or OpenAILike, GeminiLike…) compiles as before. To name a response shape, derive it from the contract or import it from /internal:

ts
import type { AnthropicLike } from '@botmesh/ai'
type Reply = Awaited<ReturnType<AnthropicLike['messages']['create']>>

Breaking (frozen data): PRESETS, DEFAULT_YES, DEFAULT_NO, AI_MESSAGES and AI_LOCALES are deep-frozen, and typed readonly. Changing them used to change the defaults of every bot in the process; now it throws a TypeError in strict mode. Extend a copy:

ts
aiPlugin({ toolConfirm: { yes: [...DEFAULT_YES, 'arre'] } })

Passing them unchanged still compiles (toolConfirm.yes/.no accept a readonly string[]).

Provider constructors now take an AIProviderConfig (model, maxTokens, effort, thinking, baseUrl), the part of AIConfig a provider reads. Passing a whole AIConfig held in a variable still compiles, but an object literal with plugin fields now fails TypeScript's excess-property check (TS2353), because providers never read them:

ts
new AnthropicProvider(client, { model, persona })   // before: compiled; now: TS2353
new AnthropicProvider(client, { model })            // drop the plugin fields
new AnthropicProvider(client, cfg)                  // or pass a variable typed AIConfig

GenerateInput.onStreamEnd receives a named AIStreamEndInfo; its contract (once, after the last chunk, only on a normal end) is in Upgrade notes: channels & plugins.

HTTP, Graph and scaffolder packages ​

@botmesh/http: closed SecureFetchOptions. The options of secureFetch and fetchBuffer no longer extend RequestInit. They hold the request fields the client honours (method, headers, body, signal) and its policy (allowHttp, allowPrivateHosts, timeoutMs, maxBytes, maxRedirects, resolver, fetch).

  • Breaking (types only): redirect is gone. It was always overridden with 'manual', because the client follows redirects itself and validates each hop; use maxRedirects (0 refuses any redirect).
  • The other RequestInit fields (cache, keepalive, integrity...) still type-check through a @deprecated overload (LegacySecureFetchOptions) and are still forwarded to fetch. They stop being accepted at stable.
  • Streaming uploads need no extra field: with a ReadableStream (or async iterable) body, the client sets the duplex: 'half' that fetch requires. Drop an explicit duplex along with the other RequestInit fields.
  • A variable typed SecureFetchOptions no longer accepts browser fields (mode, credentials, window...). Remove them.
  • resolvePublicHost is now resolveHost: it resolves any host and leaves the verdict to assertSafeTarget. The old name stays as a @deprecated alias.
ts
// Before
await fetchBuffer(url, { redirect: 'follow', cache: 'no-store', maxBytes })
// After
await fetchBuffer(url, { maxRedirects: 3, maxBytes })

@botmesh/graph-core: one options object. checkGraphSignature takes { body, headers, appSecret, logger }. The positional form keeps working as a @deprecated overload with the same results. graph-core is a public package and is covered by semver like the others: a breaking change in it is a major bump.

ts
// Before
const sig = checkGraphSignature(rawBody, headers, appSecret, logger)
// After
const sig = checkGraphSignature({ body: rawBody, headers, appSecret, logger })

@botmesh/meta: session-window plumbing is experimental. What an app configures and queries stays public and covered by semver: SessionWindowManager (constructor, forScope, state, isOpen, expiresAt, pending, clearPending), SessionWindowOptions, the SessionWindowStore contract and its MemorySessionWindowStore, the report and reopen types, SessionWindowReopenedError and the constants. The hooks the provider drives (send, noteInbound, noteFailedStatus) and their RawSend type are now @experimental: they may change in a minor release. Nothing changes at runtime. See API stability.

create-botmesh: internals in /internal. The main entry is the scaffolder: scaffold, sanitizeName, getTemplate and TEMPLATE_NAMES. TEMPLATES, agentsMd, findBotMeshMonorepo and AgentsMdInfo moved to create-botmesh/internal (no semver); the main entry re-exports them as @deprecated until stable. The CLI does not change.

ts
// Before
import { TEMPLATES } from 'create-botmesh'
const files = TEMPLATES.telegram.files('my-bot')
// After
import { getTemplate } from 'create-botmesh'
const files = getTemplate('telegram').files('my-bot')

Sandbox API token ​

@botmesh/sandbox is private, but scripts that drive its web API change:

  • Breaking: POST /api/<channel>/send|fault|status|reset now needs the per-run token in the x-sandbox-token header. Read it from sandbox.token (or the CLI output), or fix it with startSandbox({ token }) / --token.
  • Requests whose Host is not loopback, or whose Origin is another site, get a 403. Pass allowedHosts / --allow-host when the hub is reached through another name on purpose.
  • Bad input is now a 4xx: unknown fields, wrong types and a body that is not a JSON object are refused, and toUserInput() throws SandboxInputError.
