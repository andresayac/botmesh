Referencia de configuración ​

Todo lo que acepta new Bot(config), los eventos que emite el bot, cómo registra logs y los errores que puedes capturar. Las demás guías explican cada función; esta página es la tabla de consulta.

ts
import { Bot, MemoryStore } from '@botmesh/core'
import { BaileysProvider } from '@botmesh/baileys'

const bot = new Bot({
  provider: new BaileysProvider({ session: 'mi-bot' }), // la única opción obligatoria
  store: new MemoryStore({ file: './store.json' }),
  lang: 'es', // textos internos: 'en' (por defecto) o 'es'
  groupMode: 'mentions',
  conversation: { timeout: '10m' },
  typing: true,
})

new Bot() valida el objeto completo y lanza un ConfigValidationError que nombra la primera opción incorrecta.

Identidad y espacio de nombres ​

Estos ids son el espacio de nombres de todo lo que escribe el bot (filas del store, datos de usuario, tareas programadas, journals durables, trazas), así que dos bots pueden compartir una base de datos.

OpciónPor defectoQué es
sessionningunoNombre corto del bot. Es el valor por defecto de botId y connectionId.
tenantId'local'Espacio del tenant.
environmentId'default'Espacio del entorno ('prod', 'staging'…).
botIdsession, si no el id del providerId estable del bot.
connectionIdsession, si no 'default'Id de la cuenta o conexión del provider.
persistRawfalseGuarda también el payload nativo del provider. Desactivado para guardar menos datos personales.

Cambiar cualquiera de ellos más adelante hace que el bot busque en otro espacio: las filas existentes quedan en el anterior.

Funciones de producción (opt-in) ​

Cada una está desactivada hasta que la configuras, y tiene su propia guía.

OpciónQué activaGuía
durabilityJournal de entrada y outbox de salida con reintentos y cola de mensajes muertosProcesamiento durable
coordinationVarias réplicas compartiendo chats en orden, un líder para las sesiones exclusivasVarias réplicas
schedulerStore, lease y zona horaria por defecto de las tareas durablesScheduler
telemetrySpans al estilo OpenTelemetry por mensaje, envío y tareaTrazas
logIdsCómo aparecen los ids de chat y remitente en los logs: 'hash' (por defecto), 'raw' u 'omit'Logs

storeConfig está obsoleta: pasa store: new MemoryStore({ file, maxMessagesPerChat, autoSaveInterval }).

Duraciones ​

Toda opción de duración acepta un texto o un número de milisegundos. Incluye todas las opciones cuyo nombre termina en Ms (typing.minMs, coordination.turnWaitMs, scheduler.tickMs, durability.outbox.backoff.baseMs…):

EscribeSignifica
500500 ms
'500ms', '30s', '2m', '1h', '1d', '1w'las unidades habituales
'30 seconds', '5 minutes', '2 hours', '1 day'también los nombres largos (en inglés)
ts
const bot = new Bot({
  provider,
  typing: { minMs: '800ms', maxMs: '3s' },
  durability: { pollMs: '1s', outbox: { inlineMaxMs: '15s', backoff: { baseMs: '1s', capMs: '1m' } } },
})

Un valor inválido falla al construir el bot y nombra la opción:

text
ConfigValidationError: Invalid config.durability.pollMs: expected a duration ('500ms', '30s', '10m', '1h') or milliseconds, got string ("soon")

parseDuration('2m') (de @botmesh/core) usa la misma gramática y devuelve milisegundos.

Ciclo de vida y eventos ​

ts
await bot.start()                 // conecta el transporte; desde aquí se aceptan envíos
await bot.stop({ drain: true })   // termina antes los envíos en curso (`timeout`, por defecto '10s', limita la espera)
  • Los envíos, ediciones y ctx.delete() antes de start() o después de stop() rechazan con BotNotRunningError. Un listener de 'ready' ya puede enviar.
  • Las llamadas a start() y stop() se ejecutan de una en una, en orden.
  • Las señales de presencia (ctx.typing(), ctx.markRead()) nunca lanzan con el transporte desconectado: se omiten y cuentan en metrics().presenceSkipped.

Escucha con bot.on(evento, fn) (también bot.once y bot.off):

EventoPayloadCuándo
qrstringUn QR (o código de vinculación) para enlazar la cuenta (Baileys).
connectionConnectionUpdateCambió el estado de conexión del transporte.
readyningunoEl transporte está conectado.
started / stopping / stoppedningunoCiclo de vida. stopping llega antes del drain: cancela ahí el trabajo largo.
messageMessageContextTras cada mensaje procesado, aunque un handler lo haya consumido.
command:unknown{ ctx, command }Un /comando que nadie registró.
error{ error, ctx? }Error de un handler, hook, store o provider. Siempre se emite.
reaction, poll, call, group, presence, statusevento del providerReacciones, votos, llamadas, cambios de grupo, presencia, acuses de entrega.
handoff / resumeHandoffEvent / ResumeEventUn chat pasó a un humano / volvió al bot.

Escucha siempre 'error'

Los errores nunca tumban el proceso, así que sin listener solo quedan en el log. bot.on('error', ({ error, ctx }) => ...) es donde los reportas.

Logs ​

logger acepta un LoggerLike: pino, console o cualquier objeto con debug, info, warn y error. Providers y stores aceptan la misma opción logger. Los paquetes siempre lo llaman al estilo pino, así que un logger propio solo tiene que entender dos formas:

ts
logger.warn('provider reconnected')                  // un mensaje
logger.error({ err, chatId }, 'dispatch error')      // primero el objeto de contexto, luego el mensaje

Un error va siempre bajo la clave err, y child(bindings) es opcional. Sin logger, el bot usa su propio pino en warn (debug: true lo baja a debug); bot.logger es el logger en uso.

Los ids de chat y remitente son datos personales (teléfonos, emails), así que las líneas de log del propio bot los hashean por defecto:

logIdsLos logs muestran
'hash' (por defecto)un HMAC-SHA256 del id, 16 caracteres, estable dentro del proceso (el mismo hash que las trazas)
'raw'el id tal cual, para depurar en local
'omit'ningún id

Los cuerpos de los mensajes nunca se registran.

Errores ​

Todos se exportan desde @botmesh/core. Compruébalos con instanceof; la mayoría lleva además un code o name estable.

ErrorCuándoQué hacer
ConfigValidationErrornew Bot() recibió una opción inválida. field es la ruta de la opción.Corrige la opción que nombra el mensaje.
BotNotRunningErrorUn envío, edición o borrado antes de start() o después de stop() (code: 'BOT_NOT_RUNNING').Envía después de start(), o desde un listener de 'ready'.
ProviderErrorBase de todos los errores de envío de abajo.Captúralo para manejar cualquier fallo de envío.
UnsupportedContentErrorEl canal no puede enviar ese contenido (sin botones, sin stickers, demasiadas opciones…).Consulta ctx.supports() o envía algo más simple.
RateLimitedErrorLa plataforma limitó el envío; retryAfterMs cuando se conoce.Espera; los envíos de ctx reintentan solos una vez las esperas cortas.
RecipientUnreachableErrorEl chat no existe, bloqueó al bot o no se puede contactar.Deja de enviar a ese chat.
PayloadTooLargeErrorEl mensaje o la media supera el límite de la plataforma. MediaTooLargeError es el caso entrante (maxBytes de loadMediaOf).Envía menos, o un enlace.
OutsideSessionWindowErrorWhatsApp Cloud API: la ventana de 24 horas está cerrada.Envía una plantilla. Ver Ventana de 24 h.
MediaUnavailableErrorLa media entrante ya no se puede descargar (un mensaje reproducido, un mock sin bytes).Pide al usuario que la envíe de nuevo.
SendDeferredErrorOutbox durable: el envío no terminó dentro de inlineMaxMs; queda en cola y se reintentará.Nada; escucha 'durability:dead' para los fallos definitivos.
ConversationErrorBase de las señales de control de conversación: ConversationTimeout, ConversationCancelled, RetriesExceeded, ConversationEnded, ConversationGoto.Si envuelves un paso en try/catch, relánzala: if (e instanceof ConversationError) throw e.
ConcurrentWaitErrorEmpezó una segunda espera con otra pendiente (un c.ask() o c.retry() sin await).Usa await en cada espera.
RetryUnavailableErrorc.retry() sin una espera previa.Llámalo después de una espera.
UserDataErrorRuta, valor, TTL o namespace de ctx.user inválido, o un store sin datos de usuario (code).Ver Errores de datos de usuario.
InvalidProviderEventErrorUn provider emitió un evento mal formado; se descartó (se reporta en 'error').Corrige el provider.
LeaseLostError, ProviderNotLeaderError, CoordinationUnavailableErrorSolo con varias réplicas: se perdió el turno del chat o el liderazgo.Ver Varias réplicas.
TimeoutErrorVenció un plazo: una llamada a un modelo o herramienta de @botmesh/ai, o una espera del kit de tests como chaos.settle().Reintenta, o sube ese timeout.
